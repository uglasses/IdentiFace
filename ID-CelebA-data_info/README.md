# ID-CelebA: data_info and Reproduction Guide

ID-CelebA is derived from [CelebAMask-HQ](https://github.com/switchablenorms/CelebAMask-HQ). This repository provides our dataset's partial annotations and filtering results. Images, sketches, and LQ images should be generated by users themselves after downloading the original dataset following this guide. The procedure is consistent with Section II of the [supplementary material](../Supplementary_Material.pdf).

## 0. Overview

### Contents of this folder

| File | Entries | Description |
| --- | ---: | --- |
| `CelebA_filter_result.jsonl` | 30,000 | Filtering result for every CelebAMask-HQ image |
| `data_info_celebA.json` | 16,377 | Training-set annotations (`path` / `control_image` / `prompt` / `long_prompt`) |
| `data_info_celebA_test.json` | 1,820 | Test-set annotations, same fields as above |

The training and test sets contain 18,197 images in total, covering 5,054 identities, at 512×512 resolution, saved as `.jpg`.

### Target directory layout

All paths in `data_info` are relative to the dataset root, e.g. `"path": "CelebA-HQ-img/1.jpg"` and `"control_image": "CelebA-HQ-sketch/1_edges.jpg"`. After reproduction, the directory should look like:

```text
dataset/ID-CelebA/
├── CelebA-HQ-img/            # 18,197 GT images, 512×512, accessories removed
├── CelebA-HQ-sketch/         # {id}_edges.jpg
├── CelebA-HQ-hdLQ/                 # optional: camera-like LQ ({id}.png, 32×32)
├── data_info_celebA.json
├── data_info_celebA_test.json
└── identity_celebA.txt         # requested or generated from facial recognition models
```

### Pipeline order

1. Keep images according to `CelebA_filter_result.jsonl` and resize them to 512×512
2. Remove accessories: detection → editing → quality check
3. Generate sketches from the **accessory-removed GT**
4. Generate LQ images from the **accessory-removed GT**

Sketches and LQ images must be generated after step 2; otherwise eyeglasses, hats, etc. will remain in the conditional images.

## 1. Filtering Result `CelebA_filter_result.jsonl`

Each line is one record. `image` is a file name under CelebAMask-HQ `CelebA-HQ-img/`, and `reason` is the filtering verdict:

```json
{"image": "0.jpg", "reason": "Yes"}
{"image": "1000.jpg", "reason": "Not front face"}
```

**Only images with `reason == "Yes"` belong to the final ID-CelebA dataset**; all others were filtered out. The meaning of each value is listed below (corresponding to Table 2 of the supplementary material):

| `reason` | Count | Meaning |
| --- | ---: | --- |
| `Yes` | 18,197 | Kept; these make up the whole ID-CelebA dataset |
| `Not front face` | 11,620 | Judged as non-frontal by Qwen3-VL (prompt: `prompts/front_prompt.txt`) |
| `Blocked by VLM` | 105 | The VLM API refused to answer due to content review |
| `AI Low quality` | 60 | Degraded quality after accessory removal (Edit Degradation) |
| `AdaFace detection` | 18 | AdaFace failed to detect a face in the image |

After downloading the original CelebAMask-HQ, you only need to keep the images with `reason == "Yes"`. The original CelebAMask-HQ images are 1024×1024 while ID-CelebA uses 512×512, so resize them while copying:

```python
import json
import os

from PIL import Image

SRC = "CelebAMask-HQ/CelebA-HQ-img"        # original CelebAMask-HQ images
DST = "dataset/ID-CelebA/CelebA-HQ-img"

os.makedirs(DST, exist_ok=True)
with open("ID-CelebA-data_info/CelebA_filter_result.jsonl", encoding="utf-8") as f:
    keep = [r["image"] for r in map(json.loads, f) if r["reason"] == "Yes"]

for name in keep:
    img = Image.open(os.path.join(SRC, name)).convert("RGB")
    img.resize((512, 512), Image.Resampling.LANCZOS).save(os.path.join(DST, name), quality=95)

print(f"kept {len(keep)} images")  # 18197
```

Then copy `data_info_celebA.json` and `data_info_celebA_test.json` into `dataset/ID-CelebA/`.

## 2. Accessory Removal

In forensic identification, accessories (eyeglasses, hats, earrings, etc.) occlude key facial landmarks and are typically absent in standard identity photos. Training on images with accessories may cause the model to rely on non-biometric cues, so accessories are detected and removed to restore the underlying facial structure.

> Some images with `reason == "Yes"` originally contained accessories and were successfully edited in our version. When reproducing, run this section on all 18,197 images obtained in step 1.

### 2.1 Accessory detection (SegFace)

Use the facial semantic segmentation model [SegFace](https://github.com/Kartik-3004/SegFace) to detect accessory regions, and select images containing **any** of `hat`, `ear_r` (earrings), or `eye_g` (eyeglasses).

First download the SegFace weights to `SegFace/weights/convnext_celeba_512/model_299.pt` as described in the repository root `README.md`. The script only detects `hat,eye_g` by default, so `ear_r` must be added explicitly via `--parts`:

```bash
python SegFace/batch_detect_accessories.py \
    --input_dir dataset/ID-CelebA/CelebA-HQ-img \
    --output_jsonl dataset/ID-CelebA/accessories.jsonl \
    --parts hat,ear_r,eye_g \
    --device cuda \
    --skip_done
```

The output is JSONL with one image per line. The field name is spelled `accesories` in the code; its value is an empty string when no accessory is detected, otherwise the string form of the list of detected parts:

```json
{"image": "1.jpg", "accesories": ""}
{"image": "12.jpg", "accesories": "['eye_g', 'hat']"}
```

`--skip_done` allows resuming an interrupted run. Collect the non-empty records into a to-edit list:

```python
import ast
import json

todo = {}
with open("dataset/ID-CelebA/accessories.jsonl", encoding="utf-8") as f:
    for r in map(json.loads, f):
        if r["accesories"]:
            todo[r["image"]] = ast.literal_eval(r["accesories"])

with open("dataset/ID-CelebA/to_edit.json", "w", encoding="utf-8") as f:
    json.dump(todo, f, indent=2)
print(f"{len(todo)} images need accessory removal")
```

### 2.2 Accessory removal (Qwen-Image-Edit)

Use the image editing model [Qwen-Image-Edit](https://huggingface.co/Qwen/Qwen-Image-Edit) to inpaint the images selected above. Based on the detected parts, guide the model with a **short, explicit** prompt to remove the corresponding accessories, e.g.:

- `eye_g` → `Remove the eyeglasses from the person.`
- `hat` → `Remove the hat from the person.`
- `eye_g` + `hat` → `Remove the eyeglasses and the hat from the person.`

Qwen-Image-Edit requires a recent version of `diffusers`, while this repository's training environment pins `diffusers==0.30.0`. **A separate environment is recommended**:

```bash
pip install git+https://github.com/huggingface/diffusers transformers accelerate
```

```python
import json
import os

import torch
from diffusers import QwenImageEditPipeline
from PIL import Image

ROOT = "dataset/ID-CelebA"
SRC = f"{ROOT}/CelebA-HQ-img"
OUT = f"{ROOT}/edited"
PART_NAMES = {"eye_g": "eyeglasses", "hat": "hat", "ear_r": "earrings"}
SEED = 0

os.makedirs(OUT, exist_ok=True)
with open(f"{ROOT}/to_edit.json", encoding="utf-8") as f:
    todo = json.load(f)

pipe = QwenImageEditPipeline.from_pretrained("Qwen/Qwen-Image-Edit", torch_dtype=torch.bfloat16)
pipe.to("cuda")  # use pipe.enable_model_cpu_offload() instead if VRAM is insufficient

for name, parts in todo.items():
    items = " and the ".join(PART_NAMES[p] for p in parts)
    prompt = (
        f"Remove the {items} from the person. "
        "Keep the identity, facial features, expression and background unchanged."
    )
    img = Image.open(os.path.join(SRC, name)).convert("RGB")
    out = pipe(
        image=img,
        prompt=prompt,
        negative_prompt=" ",
        true_cfg_scale=4.0,
        num_inference_steps=20,
        generator=torch.manual_seed(SEED),
    ).images[0]
    # Qwen-Image-Edit may change the output resolution; resize back to 512×512 and keep the file name
    out.resize(img.size, Image.Resampling.LANCZOS).save(os.path.join(OUT, name), quality=95)
```

Write the edited results to `edited/` first. **Do not overwrite** `CelebA-HQ-img/` directly; replace the originals only after they pass the quality check in 2.3.

### 2.3 Edit quality check (Qwen3-VL)

Use Qwen3-VL with the prompt `prompts/AIEditDetect_prompt.txt` to check the edited images, and filter out those with severe AI-editing defects (missing or melted facial features, broken facial structure, duplicated parts, etc.).

> Note that the verdict is the opposite of Section 1: this prompt asks whether severe defects exist, so **`Yes` means the edit failed** and `No` means it passed.

The example below calls Qwen3-VL through an OpenAI-compatible API, which works with a local vLLM deployment (e.g. `Qwen/Qwen3-VL-8B-Instruct`) or a cloud API (e.g. `qwen3-vl-plus` on Alibaba Cloud Model Studio):

```python
import base64
import json
import os

from openai import OpenAI

ROOT = "dataset/ID-CelebA"
client = OpenAI(base_url=os.environ["VLM_BASE_URL"], api_key=os.environ.get("VLM_API_KEY", "EMPTY"))
MODEL = os.environ["VLM_MODEL"]

with open("prompts/AIEditDetect_prompt.txt", encoding="utf-8") as f:
    prompt = f.read()

results = {}
for name in sorted(os.listdir(f"{ROOT}/edited")):
    with open(f"{ROOT}/edited/{name}", "rb") as f:
        b64 = base64.b64encode(f.read()).decode()
    resp = client.chat.completions.create(
        model=MODEL,
        temperature=0,
        messages=[{"role": "user", "content": [
            {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64}"}},
            {"type": "text", "text": prompt},
        ]}],
    )
    answer = (resp.choices[0].message.content or "").strip()
    results[name] = "bad" if answer.lower().startswith("yes") else "ok"

with open(f"{ROOT}/edit_check.json", "w", encoding="utf-8") as f:
    json.dump(results, f, indent=2)
```

Handle the results as follows:

- `ok`: overwrite the original image in `CelebA-HQ-img/` with the one in `edited/`.
- `bad`: change the random seed (`SEED`) or slightly adjust the prompt, rerun 2.2, and check again.
- Images that still fail after several retries (or for which the VLM refuses to answer due to content review) were removed from the dataset in our pipeline, and their entries should also be deleted from `data_info_celebA*.json`. The 60 images removed this way in our original pipeline are the `AI Low quality` entries in `CelebA_filter_result.jsonl`.

Because diffusion-based editing is stochastic, reproduced images will not be pixel-identical to our version, but they are fine to use as long as they pass the quality check.

## 3. Sketch Generation

Sketches are generated from the **accessory-removed GT** using the MM-CelebA-HQ processing script [`create_sketch.py`](https://github.com/IIGROUP/MM-CelebA-HQ-Dataset/blob/main/create_sketch.py) from [MM-CelebA-HQ](https://github.com/IIGROUP/MM-CelebA-HQ-Dataset), together with the pretrained GAN sketch simplification model [sketch_simplification](https://github.com/bobbens/sketch_simplification) by Simo-Serra et al. The process has two steps:

1. Convert to grayscale, apply a 3×3 Gaussian blur, then extract Sobel edges from both the image and its inverse and blend them, producing a detailed but noisy edge map (an alternative to Photoshop's Photocopy filter);
2. Feed the edge map into the GAN sketch simplification model (`sketch_gan.t7`) to obtain a sketch resembling a hand-drawn line drawing, saved as `{id}_edges.jpg`, which matches the `control_image` naming in `data_info`.

### Environment: just use the CPU

The script depends on `torch==0.4.1` and `torchvision==0.2.1` (it needs `torch.utils.serialization.load_lua` to read Lua Torch `.t7` weights, which was removed in newer PyTorch). torch 0.4.1 was only built against CUDA 8/9 and **does not support recent GPUs** (e.g. RTX 30/40/50 series), so simply run it on the CPU. The model is fully convolutional, and CPU inference on 512×512 images is entirely practical; to speed things up, split the images into several folders and run multiple processes in parallel.

```bash
conda create -n sketch python=3.6 -y
conda activate sketch

# Linux
pip install https://download.pytorch.org/whl/cpu/torch-0.4.1-cp36-cp36m-linux_x86_64.whl
# Windows
pip install https://download.pytorch.org/whl/cpu/torch-0.4.1-cp36-cp36m-win_amd64.whl

pip install torchvision==0.2.1 --no-deps
pip install "numpy<1.20" pillow six opencv-python==4.5.1.48
```

### Required changes before running

The original `create_sketch.py` has a few issues that cause errors or unexpected behavior. Fix them first:

1. **Weight file name**: `cache = load_lua(args.modelname)` tries to open a file named `GAN`; change it to `cache = load_lua(model["filename"])` (i.e. `model_gan.t7`).
2. **`use_cuda` argument**: it is a positional argument with `type=bool`, and `bool("False")` evaluates to `True`. To use the CPU, pass an empty string `""`, or simply set `args.use_cuda = False` in the code.
3. **Windows paths**: the output file name is built with `image_path.split("/")`, which yields wrong names on Windows. Change it to `os.path.splitext(os.path.basename(image_path))[0]`, or run under Linux/WSL.
4. **Weight download**: the script calls `wget` to download the model, which is usually unavailable on Windows. Download [sketch_gan.t7](https://esslab.jp/~ess/data/sketch_gan.t7) manually, rename it to `model_gan.t7`, and place it in the working directory (MD5: `3a5b4088f2490ca4b8140a374e80c878`); the script will then skip the download.

### Running

The positional arguments are `modelname use_cuda data_path save_path`. Use the `GAN` model:

```bash
python create_sketch.py GAN "" \
    dataset/ID-CelebA/CelebA-HQ-img \
    dataset/ID-CelebA/CelebA-HQ-sketch
```

Afterwards, `CelebA-HQ-sketch/` should contain 18,197 files (minus any images additionally removed in 2.3), named like `1_edges.jpg`.

## 4. LQ Generation

ID-CelebA has two kinds of low-quality (LQ) conditional images:

| Name | Resolution | Degradation | How it is generated |
| --- | --- | --- | --- |
| $I_{LQ}$ | 8×8 | Bicubic downsampling | Generated on the fly from GT during preprocessing; no files needed |
| $I'_{LQ}$ (camera-like LQ) | 32×32 (24×24 for real-world experiment samples) | Camera degradations incl. optical blur and realistic sensor noise | `other_tools/camera_lq_pipeline.py` |

### 4.1 Simple LQ $I_{LQ}$

$I_{LQ}$ downsamples the GT to 8×8 with bicubic interpolation and then upsamples it back to the original resolution with bicubic interpolation. Step 4 of `preprocess_dataset.py` generates it directly from the GT and encodes it into VAE features (`--lq_low_res 8`, bicubic by default), so nothing needs to be prepared in advance. To inspect the image, use:

```python
from PIL import Image

gt = Image.open("dataset/ID-CelebA/CelebA-HQ-img/1.jpg").convert("RGB")
lq = gt.resize((8, 8), Image.Resampling.BICUBIC).resize(gt.size, Image.Resampling.BICUBIC)
```

### 4.2 Realistic LQ $I'_{LQ}$

$I'_{LQ}$ is closer to raw surveillance footage and is generated with `other_tools/camera_lq_pipeline.py`. The script simulates a two-stage camera sampling process:

1. **Optical stage**: slight white-balance shift, optical Gaussian blur, and random motion blur;
2. **Sensor stage**: area integration with sub-pixel phase down to the target resolution; shot noise, dark current, read noise, row/column fixed-pattern noise, local banding, and hot pixels injected in the Bayer RAW domain; quantization to 6–8 bits, followed by bilinear demosaicing and a weak ISP (gamma); finally, a surveillance-style slight desaturation and dimming.

Degradation parameters are randomly sampled per image, and the overall result is fixed by `--seed`.

```bash
python other_tools/camera_lq_pipeline.py \
    --input-dir dataset/ID-CelebA/CelebA-HQ-img \
    --output-dir dataset/ID-CelebA/LQ \
    --target-size 32
```

The output is `dataset/ID-CelebA/LQ/lq_32/{id}.png` at the native 32×32 resolution (upsample when using it). Common options:

- `--target-size`: target resolution, one of 8/12/16/24/32/64. ID-CelebA uses 32; real-world experiment samples use 24.
- `--strength`: global degradation strength multiplier, default 1.0.
- `--seed`: random seed, default `20260409`.
- `--isp-gamma`: ISP gamma, default 0.92.
- `--no-surveillance-grade`: disable the surveillance-style desaturation and dimming.

Step 5 of `preprocess_dataset.py` calls the same degradation pipeline and can generate the native PNGs (`InternData/hard_lq_pixel_32x32/`) together with the corresponding VAE features during preprocessing.

## 5. Subsequent Preprocessing

Once the data is ready, run preprocessing as described in the repository root `README.md`. ID-CelebA uses a resolution of 512:

```bash
python preprocess_dataset.py \
    --dataset_root dataset/ID-CelebA \
    --image_dir dataset/ID-CelebA \
    --input_metadata dataset/ID-CelebA/data_info_celebA.json \
    --models_dir models \
    --resolution 512 \
    --use_long_prompt \
    --hard_lq_camera_target_size 32
```
